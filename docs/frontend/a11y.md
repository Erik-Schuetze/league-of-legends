# Accessibility contract

Normative. WCAG 2.1 level AA is the floor for this site, and the sections below
are what that means in practice for this interface. Where the guide gives a
number, the number is verified by `tools/contrast-audit.mjs` (colour) or by
`mockup/tools/check-mockup.mjs` (structure, focus, targets, motion) - not by
hand-waving.

Audience: implementation agents. Everything here is testable.

---

## 1. The contract in one list

| Requirement | Where it is enforced |
| --- | --- |
| Text contrast ≥ 4.5:1, large text ≥ 3:1 | `tools/contrast-audit.mjs` exits non-zero |
| Non-text contrast ≥ 3:1 (rings, borders, control outlines) | same tool, `1.4.11` rows |
| Never colour alone | §4.5 |
| Visible focus ring on every interactive element, never removed | §3 |
| Full keyboard operation, logical order, no traps | §2, §6 |
| 44×44px targets at ≤ 480px, 24×24px floor elsewhere | §5 |
| Motion removable, no parallax, no autoplay | §7 |
| One `h1` per page, labelled landmarks, skip link | §8 |
| Every statistic carries its sample size | `components.md` §6 |
| No request leaves the origin at render time | `mockup/tools/check-mockup.mjs` |

## 2. Keyboard

- Tab order follows DOM order. No positive `tabindex` anywhere.
- Every control is reachable and operable with Tab, Shift+Tab, Enter, Space,
  arrows and Escape as its role requires.
- `Escape` closes the topmost overlay: Dialog, Drawer, Popover, Tooltip,
  ExportMenu, Combobox listbox.
- Opening an overlay (Dialog, Drawer) moves focus into it and returns focus to
  the trigger on close. The trigger element, not a nearby heading.
- Nothing below a modal is focusable while it is open.
- In-page navigation targets (`id` on a section that a link points at) carry
  `scroll-margin-block-start: var(--nav-height)` so the sticky nav never covers
  the heading that just received focus. The shell sets this on `main`.
- The table's sort control is a real `<button>` inside `<th>`, so sorting is
  keyboard reachable, and the current sort is exposed with `aria-sort` on the
  header cell.

## 3. Focus

The ring is part of the design language, not a browser default we tolerate.

```css
--focus-ring-inner: 0 0 0 2px var(--c-cream);  /* separates ring from the box */
--focus-ring:       0 0 0 4px var(--c-blue);
--focus-shadow: var(--focus-ring-inner), var(--focus-ring);
```

Rules:

- Use `:focus-visible`, never `:focus` alone, so a mouse click does not paint a
  ring while a Tab press always does.
- Never `outline: none` without a replacement ring in the same declaration
  block.
- The inner cream stop exists because a blue ring on a blue fill (a primary
  button, a selected segment) would otherwise vanish. Do not drop it.
- Focus is not animated slower than `--dur-fast`. The ring must be present on
  the first painted frame after the key press.

### 4.2 The two exceptions, and their limits

- `--c-text-disabled` is below 4.5:1 **on purpose**. It may only be used on an
  element that is genuinely unavailable (`disabled`, `aria-disabled="true"`).
  Disabled text must never be the only way to communicate why something is
  unavailable: the reason goes in a `hint` or a `note`.
- `--c-rule #cbbba2` at 1.57:1 is a **divider**, not a boundary. It may
  separate two regions; it may never be the only thing that identifies an
  interactive control's edge. Control edges use `--c-control-border` (4.50:1 on
  cream) or `--ring` (blue).

### 4.3 Large text

Only `--step-3` and above qualify (≥ 24px, or ≥ 18.66px bold). At AA that
lowers the floor to 3:1, which this palette clears everywhere. Do not use this
to justify muted 20px text: `--c-text-muted` already passes 4.5:1, use it.

### 4.4 Tints

`--tint-accent` (7%) and `--sig-*-tint` (8%) are measured against the text they
carry (`win text on tinted row`, `loss text on tinted row`). If you introduce a
new tint, add the pair to `tools/contrast-audit.mjs` and re-run before use.

### 4.5 Never colour alone

Verified hue separation is poor by design: blue ↔ up is 1.03:1, blue ↔ down
1.20:1, up ↔ down 1.24:1. A red/green pair would fail for most colour-vision
deficiencies, so every signal carries a second channel:

- **Deltas** carry an arrow glyph and a sign, and are read out as
  "+1.2 points" - the `DeltaIndicator` never renders a bare tinted number.
- **Tier badges** carry the letter (S+…D) as their primary encoding; tint is
  redundancy.
- **Roles** carry a text label or letter, not a colour.
- **Heatmap cells** print their value. The heat scale is a secondary read.
- **Withheld cells** carry the text `withheld`, not a grey fill alone.
- **Selected rows** carry the accent tint *and* a raised ring.

## 5. Targets and pointer

| Breakpoint | Controls | Prose links |
| --- | --- | --- |
| ≤ 480px (phone) | ≥ 44×44px | ≥ 24×24px, or inline in a sentence |
| 481–767px | ≥ 44×44px | ≥ 24×24px, or inline |
| ≥ 768px (pointer) | ≥ 44×44px for default sizes; compact `sm` sizes ≥ 24×24px | ≥ 24×24px |

- The floor comes from `--touch-target: 44px`. Compact sizes (`size="sm"`) are
  a **desktop density** affordance. Below 768px every component restores the
  44px box in its own stylesheet - the label may still shrink, the box does
  not. This is per-component, because a global rule cannot out-specify scoped
  component CSS.
- A stretched link (`app.css` `.stretch-host` + `.stretch-link`) is measured by
  its host box, because its `::after` paints the clickable area over the whole
  card.
- Exception used deliberately: WCAG 2.5.8's **spacing** exception applies to a
  lone link in a paragraph or list item. The checker honours it; do not use it
  to justify a dense row of small targets.
- Hover is never the only way to reach a value or an action. Anything hoverable
  is also focusable.

## 6. Overlays

| Component | Focus | Dismiss | Notes |
| --- | --- | --- | --- |
| Dialog | moved in, trapped, returned | Escape, close button, scrim click | `aria-modal="true"`, labelled by its title |
| Drawer | moved in, trapped, returned | Escape, close button | same contract as Dialog |
| Popover | moved in on open | Escape, outside click | `aria-expanded` on the trigger |
| Tooltip | stays on the trigger | Escape, blur, pointer leave | `aria-describedby`; never the only label |
| Toast | not stolen (polite live region) | dismiss button, timeout ≥ 6s | a toast never carries information available nowhere else |

## 7. Motion

The whole motion budget is `--dur-fast/base/slow` and one float keyframe.

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --dur-fast: 1ms; --dur-base: 1ms; --dur-slow: 1ms;
    --lift: none; --float-amp: 0px;
  }
}
```

- Because components read their durations from the tokens, a component that
  forgets a local media query still stops animating. That is the mechanism:
  **no component needs its own reduced-motion block to be safe**, and the
  checker proves it by measuring every animated element's computed duration.
- Decorative float (`FloatingTile`) is never applied to anything interactive.
- Nothing flashes more than three times per second. There is no autoplay, no
  parallax and no scroll-linked animation.

## 8. Structure and semantics

- One `<h1>` per page (`PageHeader`). Heading levels descend without skipping;
  `SectionHeader` takes `level` for exactly this reason.
- `<main id="main" tabindex="-1">` once per page, preceded by a
  `.skip-link` that is visible on focus and carries the 44px target.
- Landmarks: `<header class="nav">` for the site bar, `<nav>` for each
  navigation group, `<footer>`, one `<main>`. A `nav` needs a label when it is
  not the only one on the page (`aria-label="Breadcrumb"`).
- Tables are real `<table>` with `<caption>` or an adjacent `SectionHeader`,
  `<th scope="col">` and `aria-sort` on the sorted column.
- Numeric columns are marked `numeric` for alignment and read the raw number;
  the unit lives in the header.
- Every `svg` is either `aria-hidden="true"` or labelled.
- Every input has a programmatic label. The components generate their ids with
  `$props.id()`, which is stable between prerender and hydration; ids that come
  from a label string alone would collide the moment two controls share a
  label, so components append the instance id.
- `aria-labelledby` targets are resolved in the built HTML - the checker fails
  the build-facing run if any id is missing or duplicated.
- Live regions: `role="status"` for the filter summary and toasts (polite),
  `role="alert"` for Banner tones `warning`/`danger` only. A live region
  announces a *change*; it never holds the only copy of the value.

## 9. Language and reading

- `lang="en"` on `<html>`; a foreign-language term gets its own `lang`.
- Abbreviations in chrome (`EUW`, `TOP`, `n`, `pp`) expand on first use: at
  minimum a `title` or the visually-hidden expansion the components already
  render (`SampleAnnotation` expands `n` to "sample size").
- No text is conveyed only by position ("the box on the right").
- Text survives 200% zoom and 320px-wide reflow without loss or horizontal
  scrolling of the page (tables may scroll *inside* their own container).

## 11. Manual checks that no tool here performs

Recorded as known gaps so nobody assumes they are covered:

1. **Screen reader passes.** No NVDA/JAWS/VoiceOver run has been done. The
   semantics are built to spec but unverified against a real reader.
2. **Colour-vision simulation.** Hue separation is documented as poor; the
   second-channel rule is the mitigation, not a simulation result.
3. **Zoom to 400%** and **Windows High Contrast** are only partly covered
   (`forced-colors` tokens exist; no render has been taken in that mode).
4. **Cognitive load / plain language** review of the legal pages by a human.
